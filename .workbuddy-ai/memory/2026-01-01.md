# Teddy Notes — Work Log

## Code audit & concurrency hardening

Deep multi-dimension audit (logic, perf, races, threading, leaks,
error-handling) of the `teddynotes/` package. Report at `CODE_AUDIT.md`.

**Fixes applied**
- `editor.py` `_schedule_save`: worker now operates on an immutable snapshot;
  never reads live `current_note`. Idle callback validates note_id+html.
- `editor.py` `flush_save`: clears `_pending_save_data` only after successful
  commit (was dropping edits on failure). Added `_is_current_pending` +
  `_on_background_save_failed`.
- `database.py` `get_connection`: central rollback-on-error safety net
  (`conn.in_transaction` check). Added `_write_transaction`; `save_note` uses it
  and dispatches `_notify_change` outside the lock.
- `editor.py` `_register_attachment_scheme`: replaced reliance on module-global
  `_GLOBAL_DB` with per-request `_db_for_request()` via
  `webview._teddy_db`; `_build_ui` stamps the attribute.
- `window.py`: `_cleanup()` made idempotent (`_cleaned_up` flag) since
  close-request + destroy + app do_shutdown all call it; removed dead
  `push_by_tag(...) if False else ...` branch in `open_note`.

**Documented, not changed**
- `save_note` silent plaintext fallback for locked notes (availability vs
  confidentiality UX decision).
- `ConfigManager.get_default(db)` in-place `db` reassignment (safe today: single
  shared DB).

**Note:** sandbox Bash/grep were unavailable ("Connection lost"), so the test
suite could not be executed; findings confirmed via static analysis.
